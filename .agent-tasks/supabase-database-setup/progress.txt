## Codebase Patterns

- Supabase migrations go in `supabase/migrations/` with timestamp prefix format: `YYYYMMDDHHMMSS_description.sql`
- All game-related tables use `gambit_` prefix for namespacing
- Foreign keys to auth.users go through `profiles` table, not directly
- Use PostgreSQL enums for constrained value sets (status, alignment)
- App uses in-memory GameService for testing; actual Supabase types in `app/types/supabase.ts`
- RLS policies should check both player membership AND host access where appropriate
- Realtime only enabled for tables that need client subscriptions (games, players, actions, statuses)

  - `supabase/migrations/20260125000001_enable_realtime.sql` - Updated table names

- **Learnings:**
  - Original migrations used wrong table names (games vs gambit_games)
  - The `supabase.ts` types file reflects actual remote database, not local migrations
  - Tests use in-memory mocks so migration changes don't break tests
  - Validation (typecheck + tests) doesn't validate SQL syntax - only TypeScript
  - Comprehensive migration updates are sometimes more practical than incremental changes
  - PostgreSQL enums provide type safety at database level vs CHECK constraints
