## Codebase Patterns

- **Utils location**: Game-specific utility functions go in `app/utils/` (e.g., characterAssignment.ts)
- **Services location**: Business logic services go in `app/services/` with class + singleton pattern (same as registries)
- **TypeScript types location**: Core game types go in `app/types/game.ts`, Supabase generated types in `app/types/supabase.ts`
- **Validation command**: Use `npm run validate` to run both typecheck and tests
- **Type unions over enums**: Use string literal union types (e.g., `type GamePhase = 'lobby' | ...`) rather than TypeScript enums for better tree-shaking and JSON compatibility
- **Constants alongside types**: Export const arrays (e.g., `GAME_PHASES`) alongside type unions for runtime validation and iteration
- **Testing framework**: Vitest configured in `vite.config.ts`, tests go in `app/**/*.test.ts`
- **API routes location**: React Router file-based routes in `app/routes/`, use `api.*.tsx` naming for API endpoints (e.g., `api.games.create.tsx` → `/api/games/create`)
- **API route pattern**: Export `action` function for POST/PUT/DELETE, use `loader` for GET. Return `new Response(JSON.stringify(data), { status, headers })` for JSON responses
- **Type guard pattern**: Use `isX(value: unknown): value is X` pattern with const arrays for validation
- **Registry pattern**: Class-based registries in `app/registry/` with Map storage, export both class (for testing) and singleton instance (for production)
